# 双打普通落地球的同侧后撤接球

## 问题与修复

- 原有同侧后撤优先仅适用于高吊球／高度超过 2.45m 的球。普通斜线球主要
  比较预计触球位置的跑动时间，可能把球交给距离较短、但实际追不上横向
  来球的后场搭档。
- 同侧深球分工现覆盖普通球及一跳后的球。复用正常移动和触球范围，预测
  加速度、惯性、体力、场地反弹及连续触球窗口；能接到的路线优先于不可达
  的短路线。同侧球员来得及时则自行后撤，来不及时仍允许搭档补位。
- 当前已能合法触球的搭档优先，不因未来的同侧后撤方案抢走接球责任。
- 非接球的前场球员也会针对普通穿越球后撤覆盖，不再被旧的排队挥拍目标
  固定在网前。
- 双打电脑不再用 `move` 模拟手动点击来补位。补位由 `Match.step` 的既有
  自动逻辑负责，避免持续刷新手动移动保护时间，妨碍下一拍责任切换。
- 不修改移速、球拍范围、球场范围、救球概率和网络协议。真实手动移动、
  指定接发球员和接发先落地规则保持不变；单打 AI 路径不变。

## 代码

- `src/simulation/team-play.ts`：接球可达性排序、同侧后撤及普通穿越球补位。
- `src/simulation/return-plan.ts`：抽取 `canReachBouncedReturn`，支持一跳前后
  的正常接球预测；保留 `canWaitForBounce` 仅判断未落地球的语义。
- `src/simulation/ai.ts`：移除双打电脑的伪手动补位指令。
- `tests/doubles-ground-coverage.test.ts`：新增针对性回归。

## 验证

- 修改前新增回归 4 项失败：错误分配、实际二跳漏球、普通球不后撤补位、
  电脑补位安装手动移动保护时间。
- 固定普通斜线球复现：前场球员从 z=3.40 正常后退至 z≈5.83，于第一次
  落地后完成正手回击；39 个模拟步内接球责任没有切换，没有触发救球。
- 针对性测试（新增普通球与既有高吊球）18/18 通过。覆盖四座位、换边、
  双侧、左右手／单反、三场地、30/60/120Hz、已落地球、低体力让球、
  当前合法触球优先、双电脑协作、手动移动和接发规则。
- 第一轮全量测试 634/634 通过，第二轮 639/639 通过，包括真实 WebSocket
  的 1–4 人双打、三场地和两种赛制的完整比赛与重开。最后增加“已能触球的
  搭档优先”用例后，除耗时网络矩阵外的 639/639 再次通过；结合未修改
  生产代码且已通过的网络矩阵，最终 640 项均有通过记录。
- `npm run build`（含 TypeScript 检查）及 `git diff --check` 通过。
- 本机 Node.js 四电脑 + 权威模拟，三场地各 1200 帧，平均约
  0.20–0.37ms/帧、P95 约 0.74–1.09ms/帧，仅为本机模拟开销抽样，
  不代表手机渲染性能或多房间容量。

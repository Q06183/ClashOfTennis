# 手机卡顿优化验证

用户反馈：两台手机好友对打明显卡顿。当前还没有设备型号、浏览器或手机上的性能录制，不能把桌面检查当作已复现手机故障。

## 本轮范围与验收

- 先记录同一桌面浏览器390×844、梅岚/里奥、固定1/60步长、600采样帧、120热身帧的渲染基准。CPU时间只覆盖JS模拟和图形命令提交，不是GPU完成时间。屏幕DPR在基准中显式设为1.8，模拟原手机绘图密度上限。
- 消除每个可见球路帧的两组GPU缓冲对象重建；验证属性身份稳定、轨迹坐标、累计虚线距离和落点正确。骨骼重定向复用临时矩阵。
- 手机粗指针设备默认DPR上限1.25和512阴影；持续掉帧后自动降至DPR1和简化接地阴影。恢复需30秒稳定帧间隔；启动、后台与长恢复间隔不计入降档。全部档位保留人物、球、球路/颜色/落点，球场镜头、模拟、移动与属性不变。
- 帮助页显示帧率、当前自动画质、好友网络RTT。帧率为可见帧间隔估算，用于下一轮手机诊断。
- 验证同画质渲染、手机均衡/流畅工作量、运行时降档/恢复、完整现有回归。没有服务端或网络协议更改，无需断开好友房间。

## 代码证据

旧FlightGuide.update调用LineGeometry.setPositions与Line2.computeLineDistances；Three r186实现每次创建新的InstancedInterleavedBuffer。新实现只更新既有数组并置needsUpdate。回归先在旧实现失败，再在复用实现通过。该结果证明分配模式改善，不直接证明用户手机帧率。

1.8→1.25绘图像素约减少52%；1024²→512²阴影贴图像素减少75%。流畅档DPR1且不绘制动态阴影图。上述为配置工作量变化，不等同于同比FPS提升。

数据为同一桌面浏览器的单次运行观测，计时精度和调度抖动存在影响，不宣称统计显著的CPU百分比提升；全部帧间隔中位约8.3ms，桌面未复现手机严重卡顿。低档减少阴影绘制使渲染三角形约降低45%，不是删减角色模型。原始数据见本目录JSON。`bench.html`可通过Vite开发服务直接访问，使用`?quality=high|balanced|low`；该页显式控制DPR以比较绘图工作量，不能当作手机硬件仿真。

浏览器运行时验证：模拟持续30FPS，high→balanced→low且阴影关闭；再切回high可恢复阴影，控制台无错误/警告。均衡/低档截图已检查模型和球场显示。生产7470帮助页显示实际帧率和画质；新版只变客户端静态文件，服务未重启。

99/99完整回归、生产构建、差异检查通过。代码独立复核发现并修复长帧反复重置采样窗口的问题：真正的前台慢帧保留在观测中，后台切换由visibilitychange单独清空时钟/窗口；重复300ms卡顿回归通过。阴影开关会重新编译受影响材质并释放旧阴影纹理。

下一轮手机复验：两台设备刷新，在原好友房间连续对打。若仍卡，记录设备/浏览器、右下?中的FPS和网络ms；屏幕掉帧与网络瞬移分别排查。当前没有新版本真实手机录制，不宣称已经完全解决手机卡顿。

## 2026-09-21 仅联机卡顿：快照连续播放

用户进一步确认单机完全流畅、只有联机卡顿，因此本轮针对联机同步展示链路。旧客户端对20Hz快照的位置做指数追赶，且直接复制引拍进度、挥拍时间，导致匀速跑动在包间反复减速、动作以20Hz跳步。这是代码与受控回归已确认的问题，不代表已经排除真实手机的其他网络因素。

- 新增75ms快照播放缓冲，按屏幕帧率插值人物、球和引拍，连续推进挥拍时间；过滤到包抖动。音效跟随播放时钟。缓冲会带来呈现延迟，这是平滑度与响应时间的取舍，待手机对打确认手感。
- 暂时缺包最多预测50ms；不推测击球、落地反弹、计分。换分、换人、暂停、后台恢复、重连和再赛重置单独处理。权威状态独立于展示状态，保持服务器判定。
- 帮助页新增同步频率、到包抖动、距离上一包时间，与已有FPS/RTT一起区分渲染掉帧和网络不连续。
- 专项受控回归覆盖20Hz到60Hz播放、有/无抖动的连续速度和引拍、权威状态不被修改、缺包预测上限、反弹时间、换分/暂停/再赛以及诊断。旧追赶算法速度变异系数>0.2，新算法<0.08；此为合成匀速样本，不是手机流畅度评分。完整103/103回归、类型检查、生产构建、差异检查通过。独立复核发现并修复后台清空缓冲后的权威引用回退风险。
- 两个独立WebSocket客户端经电脑Wi-Fi地址完成7:4比赛，最长6拍、84秒，角色和比分一致、再赛归零；接收间隔中位52.00ms、P95 54.59ms，RTT中位0.34ms、P95 0.69ms，4979次展示采样。数据见[network-playback.json](network-playback.json)。两端仍在同一电脑，不能代表两台手机Wi-Fi质量。
- 正式7470双浏览器房间实际加入/准备/开赛，双方比分对应，实际滑动显示快速球手势及抛球举拍。390×844帮助页显示120FPS、同步20次/秒、抖动4ms、RTT1ms；两端无控制台错误/警告。这是桌面页面接入验证，不是手机动画流畅度验收。
- 只更新客户端静态文件，7470服务未重启。下一步：两台手机刷新后重新对打；若仍卡，记录帮助页FPS、网络ms、同步频率、抖动和最近一包时间。

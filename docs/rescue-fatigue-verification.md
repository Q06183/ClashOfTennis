# 实际对局救球漏判与分间体力修复

日期：2026-09-28

> 后续用户明确要求两层体力，本文件的“单条整场保留、分间按时间恢复”已由 [单分/总体双体力](dual-stamina-design.md) 取代；救球多时刻搜索修复仍保留。下文为当时版本记录。

## 复现

1. 对手从合法触球点打出高速大角度回球，接球者提前滑动、自动跑位，经历真实落地反弹后仍漏接。旧救球只预测固定 0.20s 后的位置，此时高速球已越过场底站位边界，因而没有候选点、一次抽签也未发生。保存样本：`artifacts/rescue-fatigue/missed-opportunities.json`。
2. `resetPoint` 每分一次性增加 `0.2 × recovery`；无名为 35.6 个百分点。无名耗体低、恢复高，相比普通搭档容易每分回满。这是角色系数和大额补给叠加，并非服务端按玩家/搭档身份使用不同规则。

## 修复

- 在 0.12–0.28s 的多个时刻搜索真实可达的跳接点，保留 0.20s 优先值。限制最大位移、短时位移速度和场地边界，不跨越预测落地。
- 将选定时长写入 `player.rescue.travel`，模拟与两端渲染使用相同跳步时长；旧状态无字段仍使用默认值。
- 反手目标留出一点实际手臂余量，避免只在两帧之间勉强可达、前后两帧都错过。
- 满体力 60%、1/3 以下 5%、中间平滑过渡的概率不变。普通可接优先、每次来球一次抽签、抽中仍需实际碰球不变。
- 删除开分一次性回体。整场继承体力，分间按实际剩余休息时间，以原静止恢复率 `0.006 × recovery / 秒` 缓慢恢复；超出休息时间的 dt 不多算。新 Match 双方初始化满体力。
- 你和搭档采用完全相同的规则，角色属性和跑动/击球消耗仍可产生差异。接近满体力时，慢恢复仍可能正常回满，不能宣称“绝不会回满”。
- 比分板双方增加角色名和体力百分比；角色说明写明整场保留、分间慢恢复。

## 验证

- 体力测试：0.72/0.52 体力进入新一分不跳变；实际分间时间逐秒恢复；角色换座位结果一致；新比赛才重新初始化满体力。
- 所有原救球概率、四类动作、实际模型/蒙皮、平滑动画与合法性测试继续通过。
- 真实双 WebSocket：从对手发出实际回球、自动跑位、救球到下一分，双方同序号状态一致，动态跳步时长序列化一致；不同角色的分间体力符合相同公式。

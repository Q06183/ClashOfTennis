# 玩球首页真实对拉背景

## 问题与修复

此前首页预览是固定2.8秒的球轨迹和固定正手挥拍，人物没有真实追球，对拍节奏也不来自实际触球。现在替换为独立 `Match`：当前选中球员与模拟陪练进行真实发球、接发、落地回球和回位。

- 使用正式物理、拍触球可达判定、场地反弹、角色利手和正反手动作。
- 首页专用控制：球员追真实预测的落地接球位置，合法落地后才回击；回击后返回中间底线位置，不做无限截击循环。
- 陪练真实参与模拟，画面仍只显示当前选中模型，延续此前单球员背景约束；无需创建网络房间。
- 来回的落点随模拟时间变化，以产生正反手与左右跑位。并非人为每帧改变球方向或伪造触球。
- 镜头根据所选球员实际位置和换边方向适配，保持身体在首页菜单外可见区域。
- 选球员/换场地重新创建并释放预览世界；进入实际比赛或连接网络时释放背景模拟，实际对战参数不变。
- `dt=0`、页面隐藏及无效时间不推进；预览完整结束后自然重开，不改变实际玩家的比分/体力。

## 验证

- 每位球员×三种场地各运行60秒，均有双方真实交替回球、正手、反手和横移回位，未出现首页循环截击。
- 例：伊内丝硬地60秒观察到17次本方触拍、17次对方触拍，含9次正手、7次反手及发球，跑动1936帧，横向范围约2.66m；测试断言回球前必须已落地。
- 镜头验证桌面/手机/横屏、左右换边和多组实际跑位坐标；原首页单模型渲染断言保留。
- canvas公开诊断状态记录 `previewStroke / previewRally / previewHitter / previewBounces / previewMoving`，不暴露隐藏应用对象。
- 真实浏览器选中伊内丝，`players=1`、`athlete0=ines`；观察到45拍时反手且移动，75拍时正手。首页结构、球员页签不改。
- TypeScript、Vite及压缩构建、差异检查通过；实际7470的18个资源/编码组合一致，无服务重启；服务器和模拟源码保持不变。
- 最终前端入口 `index-CRuXqJCj.js`；真实HTTP+双WebSocket发球方向/体力验证见 `artifacts/home-real-rally-live/`。

最终全量704项：700通过、4跳过、0失败；专项7项（其中含全角色×场地矩阵及镜头矩阵）全部通过。实体手机的性能仍需用户复测。

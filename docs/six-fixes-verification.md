## 1. 救球时机、概率和最后手势

- `Match.input` 保存手势后立即检查可跳接点；每 tick 在球前进前和正常移动后继续检查。当前过高但未来跳接点合法的球也能立即起跳。
- 不再以“未来某个普通跑动窗口能接”否决当前跳接；当前已经可直接击球时仍普通击球优先。
- 概率使用**总体力**：满值90%，1/3及以下10%，smoothstep过渡；不使用本分×总体。每记来球一个随机样本，反复滑动不能刷签。
- 救回球保留最后一次手势的方向、深度、力度档位、旋转和球种，仍有既有救球减速和散布；恢复硬直保持。
- 测试验证 input 返回前起跳、未来窗口使用最后手势、伪造概率字段无效、双端一致、低总体力100个均匀样本10次触发。

## 2. 近远比例

旧版近景采用另一套低机位，与远景透视不一致。现在两者使用同一相机世界矩阵，近景仅1.9倍均匀缩放及裁切，人物/球场、近远端宽度比例不变。近景可横向取景但不改变朝向。

## 3. 身体中心瞄准

- 以真正击球时的**身体中心**为瞄准原点，去除直线前向在透视下自然产生的横向汇聚分量，再叠加用户横向手势。
- 角落直划目标与身体 x 相同，不因正反手拍位偏移向外扩散。正反手的球仍从实际触球点起飞，不瞬移到身体中心。
- 发球同规则。近远缩放不改变相同输入的目标；对边线外的真实意图仍允许出界。
- `aimOrigin` 随权威球状态记录，测试能在运动后的快照中核对实际身体原点。

## 4. 发球前站位

- 抛球前双方可点按移动；发球者限当前发球半区的底线后（11.885m+0.25m 至16.3m），不允许跨半区或进入底线内发球。
- 移动有原有速度/加速与耗体，球随发球者；实际人物位置也限制在合法发球区域内，防止惯性刹车越线。滑动启动发球时锁定其位置。接发者仍能准备移动。
- 真实WebSocket验证站位变化后从新位置发球、直划身体原点一致、比分及重赛正常。

## 5. 跑动滑步

复现到0.8/1.8m/s准备挥拍阶段：静态击球下肢覆盖了位移驱动的脚步。将下肢站姿混合限制在接近停止时才应用；发球完成后恢复脚步，不继续因旧stroke=serve固定站姿。左右手、20/30/60FPS、慢调整到冲刺均检查，实际GLB脚骨抬升通过。

## 6. 胜方庆祝

- `victoryPlayer` 只读取权威 winner，双方结果视图均展示同一获胜角色；本地动画时钟驱动持拍举臂与小跳舞步，不修改比赛状态。
- 结果页顶部写出获胜昵称/角色，底部结算卡保留比分、最长回合、时间和重赛/返回按钮，中间留给角色。
- 实际View结果路径测试验证只显示winner、动画时间推进、状态不被篡改；每位真实模型的姿态/球拍范围通过。

# 游戏界面、手感与 UI 设计修复

## 目标及检查范围

基线 `0ade02a`，从设计师角度重新检查：视觉层级、信息可读性、触控可达性、实际手势反馈、运动反馈、结算可操作性与横竖屏。实际访问 7470/7471，结合 DOM 尺寸、点击、滑动、截图与源码，不以主观“更漂亮”替代问题证据。

保持：原花园俱乐部风格、首页顺序/练习入口位置、角色和动作、近远镜头算法、球速/球路、计分规则和线上协议。手机视窗模拟不等于实体手机手感验收。

## 发现 → 修复

| 证据/问题 | 修复 |
| --- | --- |
| 手机赛制文字 top≈78px 与声音按钮的 53–87px 区间重叠 | 场地/连接/赛制/队友状态进入居中独立信息条；比分与按钮留横向间距 |
| 34px 顶部、36–37px 底部控件难点；字体多为 8–10px | 场上按钮至少 44px，常用标签 11–13px；配置目标、席位操作、赛制、关闭层按钮增大；320px 紧凑保留布局 |
| 分后建议使用深色字直接叠球场，英文大标题抢焦点 | 中文“我方/对方得分、准备二发、擦网重发”有底色卡片；建议对比稳定，不延长分间 |
| 已缓存击球却提示“到位后按滑动”，容易让玩家重复划 | 显示“击球已准备 · 到位后自动回击”，辅助说明“无需重复划动”；删除场上每球重复的救球概率算法文字（帮助仍保留） |
| 150ms 提前显示“上旋0%”；按住没划松手会跑位 | 从真实350ms蓄力起点显示；按住不划释放仅取消；微小移动保留点按，点按阈值与手势归一化保持一致 |
| 右键能开始手势；另一根手指取消可能清掉当前操作 | 只接主指针/主键；只允许匹配 pointerId 取消；完成/取消释放捕获，保留单手势生命周期 |
| 慢高吊可能被显示成“放小球” | 高吊/切削/上旋优先正确命名；短球判断只用于普通球质 |
| 手势气泡固定160px下界，窄屏/横屏边缘可能越界 | 根据实际气泡宽高及视窗安全边界计算位置 |
| 选择高吊后切换声音/镜头重建整个HUD | 原位更新对应按钮，不清掉高吊或指针状态；教学/暂停保留原限制 |
| 自动跑位环一直显示，点按与自动追球难区分 | 只对有效手动点按显示0.9秒渐隐回执；发球前也可见；按权威规则镜像合法站位范围，不冒充网络ACK |
| 发球只给文字“对角区”，缺少空间目标 | 发球前高亮当前合法对角发球区，四席位/两端/左右区均按规则计算；抛球后隐藏，不改瞄准 |
| 球尾迹由过去8帧生成，FPS不同视觉速度感不同；定格还会逐帧移动尾迹 | 固定时间采样尾迹，30/60/120FPS一致；按每记飞行/分数/倒带清理，救球或暂停相同时间完全冻结 |
| 复盘堆高结算面板，重开埋在滚动内容下面 | 面板分为独立滚动结果区+常驻操作区；复盘可展开；精简重复庆祝信息，主操作44px；普通手机同屏看到比分、复盘入口、重开 |
| 隐藏提示时右侧控件跑到左下；新教学卡与顶部条挤在一起 | 控制列 margin-left:auto；教学卡下移避开信息条；短屏只留必要提示，横屏仍有独立定位 |
| 弹层Tab可离开可见内容 | 限定焦点在最上层可见弹层，排除inert/隐藏详情；Escape取消退出/关闭帮助/继续暂停 |

## 设计合理性 review

- 不增加场上付费/成长/复杂设置，内容越靠近实际操作越简洁。
- 高亮仅表示规则允许区域，不承诺当前手势合法；点按环是输入回执，不是已到位。
- 球路识别和缓存文案只描述已有逻辑，不提供额外自动击球。
- 结果主操作常驻，不扩大面板挤掉原有庆祝动作；320px短屏保留主体球员和关键比分。
- 与基础动画/救球/双打回归一起运行。新渲染组件加入原有GPU无关测试夹具，不通过跳过旧断言掩盖回归。
- 新组件开销：一个发球区组、短时间球历史；无依赖、无录屏、无网络采集。

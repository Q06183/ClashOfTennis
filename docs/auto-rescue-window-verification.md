# 自动侧扑与0.5秒补滑窗口（2026-09-29）

用户已确认：无需先滑动，接不住时自动尝试扑救；在真实触球位置，双方人物与球一起定格最多0.5秒。提前有手势则直接回球，未输入则等待补滑，超时恢复原球路，不自动回击或倒带。

## 实现

- 移除救球启动对待处理手势的依赖；普通站位/跑动/等待弹跳能接到时仍优先普通接球。
- 保留原总体力概率90%→10%、每来球一次抽签、3.5米侧向横移上限。不增加前后位移或手臂长度。
- 搜索未来0.24～0.72秒可达点，必要时预测第一次合法落地后的回弹；实际判定仍使用权威物理和球拍触球范围，不根据预测直接授予击球。
- 新侧扑采用平滑位置曲线，候选按峰值速度≤9m/s、曲线峰值加速度≤65m/s²筛选。较远侧扑通常约0.5～0.6秒，不再用0.12～0.2秒强行跨越数米。这些是程序动画约束，并非动作捕捉或真实生物力学模型。
- 起跳/伸拍阶段随实际路程时间展开，原落地缓冲和0.5秒撑地起身阶段保留。总恢复随起跳时长增加，不再固定总计1.18秒。
- `rescueWindow` 属于服务器状态。窗口中冻结比赛时间、物理、双方运动与体力，只扣窗口剩余时间；对手击球、移动和非法输入不能解除窗口。
- 接球者有效滑动立即按该手势从冻结的真实触球点回球。已有手势则不进入窗口。0.5秒超时设置本次救球失败，原速度和原位置继续演算。
- 客户端收到窗口快照后停止外推、重置插值边界，镜头与角色骨架、球旋转保持不动；本地移动预测禁用。HUD显示剩余秒数，另一端显示对手补滑。
- 断线沿用房间暂停规则，窗口剩余时间也暂停，重连后继续；比赛结束/换分清除窗口。
- 速度调整使一些旧的“晚到200ms来球”不再物理可达。旧回归场景已提前观测来球，而不是放宽球拍接触误差。无名能正常接到的场景仍禁止扑救；专门的极限接触测试使用低总体力以隔离范围。

## 验证内容

- 无输入提前起跳、普通可接时不跳、失败彩票不重复；双方座位、提前手势和最新球质。
- 实际拍头接触、0.49秒补滑成功、0.5秒超时、非法输入/对手操作无效；冻结不消耗/恢复体力。
- 超时恢复原轨迹，迟到输入不能从已失败的侧扑补打；不会把球倒带回旧位置。
- 快照外推关闭、窗口释放不残留；View反复渲染不会继续跑步、转球或切镜头。
- 真实双WebSocket自动起跳、成功补滑、超时及断线/重连。双方同序号快照完全一致。
- 全角色实际GLB、左/右手触球与落地回归；自然伸拍/落地阶段出现的拍柄折返已修正，未放宽原连续性阈值。
- 旧小球、方向与轻街舞庆祝均纳入全量回归。

产物存放 `artifacts/auto-rescue/`。CPU姿态分镜已检查；没有浏览器/GPU或手机真人观感验收。0.5秒定格是用户明确选择的游戏辅助，不宣称为真实网球规则。
